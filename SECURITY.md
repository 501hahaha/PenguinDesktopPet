# Security policy

## Supported versions

Only the latest development version and the latest published release (once a public release exists) are expected to receive security fixes.

## Reporting a vulnerability

Do not open a public issue for a suspected credential leak, code-execution bug, authentication bypass, or data-exposure issue. After the public repository is created, use a private GitHub Security Advisory. Until then, use the project owner's private channel and do not include real secrets in the report.

When reporting, include a concise description, affected version/commit, reproduction steps that do not contain real secrets, and the potential impact. Redact tokens, account identifiers, chat messages, and personal paths before sending.

The project will not ask a reporter to paste credentials into an issue or chat. Provider-specific incidents should also be reported to the affected provider through its official security process.
